# Chaos Magic Correspondence

Eleventh framework for Abraxas Orchestra (v0.1 corpus expansion).

These mappings are design references. They guide paradigm switching, intent compression, provisional belief, results discipline, and provenance annotation. They are not runtime rules and do not implement operative magical practice.

Chaos Magic (Spares, Carroll, Hine, and related currents) treats belief as a tool, paradigms as interchangeable instruments, and results as the only non-negotiable metric. For software architecture this is the meta-framework that justifies Orchestra’s multi-system corpus: no single map is sacred; maps are selected for fit and discarded when they stop producing structure that works.

## Core Principles → Architectural Stance

| Chaos Magic principle              | Architectural expression                                      |
|------------------------------------|---------------------------------------------------------------|
| Nothing is true; everything is permitted | No framework is mandatory; all are instruments              |
| Belief as tool                     | Provisional commitment to a mapping for the duration of a task |
| Results orientation                | Eval gates, outcome metrics, Brier scores, testable structure  |
| Multiple models                    | Simultaneous or sequential use of several Orchestra frameworks |
| Paradigm shift                     | Explicit switch of primary framework mid-project               |
| Gnosis / altered focus             | Deep work modes; isolated context; reduced interrupt surface   |
| Banishing                          | Context reset; cache clear; session teardown; state isolation  |

Orchestra’s fail-closed and pragmatic-projection rules are chaos-compatible: a forced mapping that fails engineering tests is banished, not defended.

## Sigilization → Intent Compression

Austin Osman Spare’s sigilization compresses a statement of intent into a glyph that bypasses discursive noise. Architecturally:

| Sigil concept              | Architectural expression                                      |
|----------------------------|---------------------------------------------------------------|
| Statement of intent        | Explicit user/system goal string                              |
| Letter deletion / glyph    | Compression into a short code, token, or module name          |
| Fire-and-forget            | Launch operation; do not re-litigate intent mid-flight         |
| Signal of completion       | Observable outcome that closes the intent loop                |

Dual-naming already performs a mild sigilization: the mechanical name is the working glyph; the symbolic name recovers the full statement when needed.

```
# mechanical: sf_energy_stress
# symbolic:   sigil_intent_energy_market_stress  (Chaos — compressed intent)
```

## Alphabet of Desire → Custom Encoding

Spare’s alphabet of desire is a personal symbolic code for states and operations. In architecture:

- Project-specific rune sets or enum vocabularies
- Internal DSLs that encode domain operations densely
- Provenance tags that are meaningless outside the system but exact inside it

Prefer small, stable alphabets. Expand only when a new state is repeatedly needed and cannot be composed from existing symbols.

## Paradigm Engine → Framework Selection Runtime

Chaos Magic’s paradigm engine is the practice of adopting a belief system long enough to work it, then dropping it. Orchestra’s framework registry is the direct analogue:

| Paradigm operation         | CLI / skill expression                                      |
|----------------------------|-------------------------------------------------------------|
| Adopt paradigm             | `do structure -f <framework>`                               |
| Overlay secondary paradigm | `do structure -f A -o B`                                    |
| Collapse / banish excess   | `do project` (pragmatic projection)                         |
| Enumerate available maps   | `do list-frameworks`                                        |
| Refuse weak map            | Fail-closed / `NOT_COMPUTABLE` / `FORCED` status            |

No paradigm is allowed to auto-promote into permanent canon without operator review (matches Orchestra’s no-auto-promotion rule).

## Banishing → Context Hygiene

Banishing rituals clear residual influence before and after work. Architectural forms:

| Banishing act              | Architectural expression                                      |
|----------------------------|---------------------------------------------------------------|
| Pre-work banishing         | Clean session; no leaked prior framework assumptions          |
| Post-work banishing        | Teardown; clear temporary correspondence caches               |
| Emergency banishing        | Hard reset of agent context; drop corrupted state             |
| Circle / boundary          | Process isolation; sandbox; capability-limited execution      |

Pair with Enochian closing Calls and Solomonic sealed contracts when those frameworks are active.

## Results Metrics → Eval Gates

Chaos Magic judges by results. Orchestra must do the same:

| Result type                | Suggested metric / gate                                       |
|----------------------------|---------------------------------------------------------------|
| Structural clarity         | Reviewer can navigate dual-named tree without symbolic help   |
| Maintainability            | Pragmatic projection not required within one release cycle    |
| Forecast / signal quality  | Brier score, calibration error, provenance completeness       |
| Authority correctness      | Capability checks fail closed; no silent escalation           |
| Paradigm fit               | Operator does not need to override framework mid-task         |

A mapping that scores poorly on these gates is a candidate for banishing or collapse, regardless of traditional prestige.

## Practical Projection Notes

- Chaos Magic is the preferred *meta*-framework when the operator must choose among Tree of Life, Numogram, Enochian, Solomonic, etc. It does not replace those maps; it governs selection and disposal.
- Sigilization is highest-leverage for naming: compress long intent statements into short mechanical identifiers while keeping symbolic recovery paths.
- Banishing discipline prevents framework residue — e.g. leftover Sephirotic assumptions when the active map is Numogram.
- Results gates should be written into project DEFINITIONS before structure is promoted. Chaos Magic without metrics decays into aesthetic preference.
- When combining with Peircean signs, treat paradigm adoption as a legisign (conventional law for the session) and individual signals as sinsigns under that law.
- When combining with Enochian, treat Calls as paradigm-entry tokens and banishing as session close.
- Orchestra’s open corpus policy is itself a chaos-magical stance: additive maps, no forced monopoly of one tradition.

Load this file when Chaos Magic, paradigm switching, sigilization, banishing, or results-gated structure is selected as primary or secondary framework — especially as a meta-overlay on any other system.
